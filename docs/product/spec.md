## 一分鐘導覽

### 下一版已確認方向（尚未實作）

- 使用者：個人單裝置，不在這次加入帳號或跨裝置同步。
- 紀錄意義：確實完成，按「完成」才建立新正式紀錄及更新日曆。
- 每個動作一次訓練只記一個重量，定義為本次實際完成的最高重量；不要求日常輸入次數與組數。
- 顯示上次已完成的重量與日期，以及歷史最高已完成重量，供使用者對照；本次欄位帶入上次重量，可調整。
- 比較前統一重量單位。舊紀錄保留供查閱，暫不納入新的上次／歷史最高比較，因為舊資料沒有完成狀態。
- 本節來自使用者在本次對話的確認，不代表下方現有程式已經改成這些行為。具體畫面、同日多次訓練的處理與舊紀錄入口仍待設計；沒有授權直接刪除歷史資料。

本次 repo 整理只調整文件與測試位置，不實作上述功能。以下章節仍描述目前的 App。

Workout Calendar 是免登入的個人健身紀錄本：選動作、記下當天訓練、看日曆與容量趨勢。手機可透過 PWA 加到主畫面；資料留在該瀏覽器的儲存空間，不會跟 GitHub 上的程式一起備份。

主要使用情境是個人記錄重量、次數、組數；這可從欄位和文件確認。實際使用者人數、程度、主要裝置、留存率與使用者研究結果未知；尚無已確認的正式目標客群定義。有氧動作雖在清單中，但沒有專用的時間／距離紀錄欄位。

核心流程：開啟 → 使用預設動作或到 Tasks 建立動作 → Schedule 新增並填寫紀錄 → 訓練時使用計時器 → Home 回看日期、Progress 回看容量。

## 容易誤會的既有規則

1. 新增紀錄預設為 0 kg、8 次、3 組，即使還沒填寫或開始做，日曆也會亮起。
2. 從 Home 按 Open Schedule，目前會切回今天，並不保留 Home 剛選的歷史日期；可再用 Schedule 日期欄切換。
3. 在 Tasks 改動作名稱或分類，既有該動作的歷史紀錄也會一起改。這是現有行為，其設計原因未知。
4. 刪除動作不會刪除歷史紀錄，但 Progress 的選單只來自現存動作，因此刪除的動作無法從該選單回看趨勢。刪除紀錄／動作沒有確認或復原流程。
5. 同樣填 100，kg 和 lb 在容量計算中會得到相同數字。這不能當成已正確統一單位的訓練成效分析。
6. 更新時的多分頁協調不等於一般編輯已有完整同步或衝突合併；一般同時編輯的安全性尚未全面驗證。

## 已知限制及待驗證

- 目前沒有外部備份；清除網站資料、換瀏覽器或換裝置，不能自動找回紀錄。
- 尚未確認鎖屏、切到背景、系統節電與耳機切換下的計時／響鈴可靠性；手機畫面截圖不能代替這些實機測試。
- 數值欄位雖有最小值提示，但處理程式未全面強制驗證合法值；尚未做完整資料品質與安全驗收。
- 動作名稱與 note 等直接放入 HTML，可能被當成網頁標記解讀；這是程式觀察到的風險，不是已完成漏洞利用測試的結論。
- 本分支曾提交並推送，沒有本次對話授權的正式部署。今天未查線上或 GitHub 後台，不能把預定的 Actions 流程說成既有 Pages 設定已生效。

## 可親自走一遍的導覽（本次未重新執行）

請用隔離的本地瀏覽器環境，不要拿正式用戶資料測試刪除。

1. 在 repo 執行 `npm run preview`，開啟終端顯示的網址。它只讀取既有 `dist/`，若產物不存在或過期，須先依 SOP 建置；本次沒有建置。
2. Tasks 新增「導覽測試動作」，選分類；到 Schedule 選它並 Add Entry。預期顯示預設 0 kg、8 次、3 組。
3. 改為 10 kg、10 次、3 組，填一段 note，重整後回到該日期。預期紀錄與 note 保留。
4. Home 查看該日期標色，Progress 選此動作及 Day。只有這筆資料時，容量應為 300。
5. 如要驗證刪除規則，僅刪剛建立的測試動作；預期該日期仍有歷史紀錄，但 Progress 無法再選該動作。

更新專用測試另見 `docs/release/sop.md`；重整成功不是更新完整驗收。
