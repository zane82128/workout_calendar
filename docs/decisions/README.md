## 先前選項及目前狀態

### 2026-10-20 實作補記

D10、D12–D19 已在 src/ 接上本地資料並進行驗證，不再只是草圖；上表保留當時討論來源，若文字提到「當時未實作」應依本節及本次驗收判讀目前狀態。D05–D08 為被新版規格取代的舊版行為，不沿用為目前規則。

- 依已確認的舊資料保留規則，實作採原 key 的加法格式：schemaVersion 2、獨立 completedEntries、備份原始字串。這是助手在授權範圍內選擇的實作方式，不冒稱使用者指定欄位名稱。
- 同日以完成操作提高當天最高，更正是明確儲存操作，可以降低錯值；不保留未記錄的每組／每次嘗試。
- 畫面由 main.js 協調，資料規則、儲存及休息計時分開，讓之後調整風格不必重寫重量計算。
- 實際結果與限制見 [重量紀錄驗收](../validation/2026-10-20-weight-records.md)。尚未部署；手機背景、鎖屏及正式 GitHub 流程不能由本地自動測試代替。

### P01：目標使用者與資料可靠性

- 選項 A：先服務單裝置個人使用，補資料匯出／匯入。少了帳號與同步負擔，但用戶需要管理備份。
- 選項 B：服務跨裝置／多人使用，加入帳號與雲端同步。使用方便，但需要討論隱私、衝突處理、維運與成本。
- 目前確認：使用者選擇個人單裝置，跨裝置不在本階段範圍；備份匯出／匯入本身尚未確認排程，不把選擇單裝置視為同意所有 A 的功能。

- 選項 A：維持「只要有紀錄就標色」，介面明確說是有輸入資料，並先統一容量重量單位。
- 選項 B：加入計畫／完成區分，重新定義日曆及圖表是否只計算完成項目。更符合訓練狀態，但增加操作及舊資料解釋問題。
