## 你可以這樣驗收

1. 在 repo 終端執行 `npm run preview`，開啟 `http://127.0.0.1:5173/workout_calendar/src/`。若伺服器已開，沿用即可；若顯示舊版，按檢查更新並套用，必要時關閉所有本地預覽分頁後重開。不要清除網站資料。
2. 動作管理新增「驗收臥推」；回紀錄選它，先按空白完成，預期出現錯誤且沒有新紀錄。
3. 選 10/18，依序完成 40、45、42.5 kg。預期同一天只有一筆 45 kg，完成時底部通知一秒消失。
4. 選 10/19，預期上次是 10/18 的 45 kg；完成 42.5 kg。選 10/20，預期上次是 42.5、最高是 45 kg。
5. 選 10/18 更正為 35 kg，預期最高重新變成 42.5 kg。刪除 10/19 前先取消一次，確認沒有刪；再確認刪除，最高應為 35 kg。
6. 改名成「驗收臥推新名」，預期舊紀錄仍為舊名；封存後不能從新增選單選它，展開封存清單恢復後，比較仍沿用。
7. 另用徒手動作明確填 0 kg；重整／離線重開，確認成功保存的紀錄仍在。舊版資料若原本存在，應仍可在該日期只讀查閱，且不進入新比較。
8. 展開休息倒數，設定短時間、開始、暫停、續跑；檢查顯示與結束提醒。聲音必須由實際設備另驗證，不能只憑 headless 測試推論耳機或鎖屏效果。

請以隔離測試資料驗收，避免更正／刪除真實訓練。以上步驟為本地候選版本，完整自動測試可用 `npm run release -- --release <未用過的版本>` 重建並重跑。

## 限制與後續

- Android／iOS 安裝模式、鍵盤遮擋、背景／鎖屏與節電下的聲音仍待實機驗收；程式已考慮安全區及 visualViewport，但桌面測試不能保證各手機行為。
- 不提供帳號、雲端同步或資料匯出；本地原始備份和紀錄會一起受清除網站資料影響。
- 多頁在每次操作前讀取最新資料，可保護一般先後寫入；沒有完整的跨頁同時編輯衝突合併。
- 本版 schemaVersion 2，不能直接回退到不認識新欄位的四頁版；需以保留新格式的相容修復版回復。測試的回復案例使用相容 v2 程式。
- GitHub Pages 設定、CI 在 GitHub 執行及正式設備升級尚未在本次操作；未合併 main、未正式發布。
